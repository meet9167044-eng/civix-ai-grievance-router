# /submit

The form opens at 5:00 PM and needs: participant/team details, project title, GitHub repo, deployed link, other basic details, and a PPT. Start this workflow no later than 4:00 PM.

1. **Repo hygiene:** README filled (deployed URL, repo URL, team, screenshots), `.env.example` present, no secrets, no leftover TODOs in visible UI text.
2. **Screenshots:** capture the citizen result card, the merged-ticket moment, the Kanban board, and the map. Save into `docs/screenshots/` and embed 2-3 in the README.
3. **PPT:** generate slides from `docs/PPT_OUTLINE.md` (5 slides, no long text). Save as `docs/Civix-HackDay.pptx` or as a PDF export.
4. **Demo rehearsal:** run `docs/DEMO_SCRIPT.md` twice on the deployed URL. Fix anything that fails.
5. **Fill the form draft:** write a short text block to `docs/SUBMISSION_DRAFT.md` with: title "Civix: AI Civic Grievance Triage & Router", one-line pitch, problem, solution, tech stack, impact, repo link, deployed link.
6. **Final check:** open the deployed link in an incognito window and on a phone. Confirm the repo is public.

Report a checklist with pass/fail for each item.
